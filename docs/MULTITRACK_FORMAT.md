# 多轨琴谱格式规范（v2）

状态：**已实现（Windows），Android 待同步**
制定日期：2026-08-28
回滚锚点：music_player_next 仓库 git tag `pre-multitrack`（beta.51, d01b811）

## 一、设计原则

1. **老格式一字不改**：现有单轨 TXT（282 首内置曲库）的解析、播放、测试行为保持逐字节不变。
2. **无开关**：播放器按文件头自动识别格式，用户无感知，界面不加任何切换项。
3. **旧版本优雅拒绝**：老版 Windows/Android 解析器遇到 v2 文件会**明确报错**（分轨标记行不是合法事件行），绝不会静默把两轨串成一锅粥。内置曲库随 EXE/APK 打包，正常用户不存在新旧错位。
4. **留后手**：全部改动在 `feature/multitrack` 分支；回滚方法见文末。

## 二、格式定义

### v1（现有，不变）

```text
# 注释
a 1
sd 0.5
p 0.25
```

### v2（新增）

在 v1 事件语法之上增加**分轨段**：

```text
#format: 2
# 曲名: 可惜没如果（双轨钢琴版）

[track main]
a 1
q 2
h 0.5

[track accomp]
s 1
d 0.5
p 1
```

规则：

1. `[track 名称]` 独占一行，开启一条新轨；名称只限 `main` 与 `accomp`（第一期）。
2. 第一条轨前可以没有标记（默认归入 `main`），但一旦出现分轨标记，其后事件归入新轨。
3. 每条轨内部语法与 v1 完全一致：`按键 拍数`，21 键 + `p`，和弦同起同落，拍数 0 < beats ≤ 64。
4. `#format: 2` 为注释行（老解析器跳过），仅作人读标识。
5. 每条轨不得为空；轨名不得重复；至少一条轨。
6. 两条轨各自独立计时，从 0 拍同时开始。

### 为什么用 `[track]` 而不是 `#track`

`#` 开头的行在 v1 里是注释，老解析器会跳过 `#track accomp` 然后把第二条轨的事件行当成主轨继续解析——正是必须避免的"串轨成粥"。`[track]` 开头的行在 v1 解析器里是"格式错误"（字段数≠2），触发明确的 ValueError/IllegalArgumentException，老版本行为可预期。

## 三、播放语义

- 每条轨沿用 v1 的半按半放时序：事件时长 = 拍数 × beat_ms，前一半按下、后一半释放。
- 多轨按绝对时间交织排程；同一时刻的**释放先于按下**处理。
- **同键冲突规则**：一个键在物理上只有一个状态。引用计数管理——第一个轨按下时发送 key_down；另一轨在按住期间"再按"同一键不再重发（避免重触发）；全部轨都释放后才发送 key_up。主旋律的起音若恰好落在伴奏同键的保持期内，会少一次重音，这是格式约束下的合理近似，制谱时应尽量避免同键重叠（识谱规范里作为检查项）。
- 暂停/停止时释放全部按住的键；继续播放时恢复保持中的键。
- 进度/ seek 以 `main` 轨的事件序号为基准（UI 行为与 v1 一致）。

## 四、兼容性矩阵

| 运行版本 | 遇到 v1 文件 | 遇到 v2 文件 |
|---|---|---|
| 新版 Windows（≥ 多轨支持） | v1 行为不变 | 正常多轨播放 |
| 旧版 Windows / 旧版 Android | v1 行为不变 | 载入时报"格式错误"（明确、安全） |
| 新版 Android（同步后） | v1 行为不变 | 正常多轨播放 |

## 五、制谱规范（AI 识谱侧）

1. 双行钢琴简谱：**上行为 main 轨素材，下行为 accomp 轨素材**；但须按小节判断实际角色——前奏段上行的琶音音型归入 accomp 轨（与低音一起），人声主旋律进入后才作为 main 轨。
2. 灰色音符（EveryonePiano 谱例）逐处判断：承担节奏骨架的照常转写；纯八度/同音加倍可省略，省略必须记录在报告里。
3. 叠置和弦（一列多个数字）按同时按键写入所在轨。
4. 反复/房子/D.S. 展开成真实播放顺序后再写入 TXT，两轨展开路线必须一致。
5. 两轨逐小节拍数分别核对；四拍小节两轨都应闭合。
6. 输出报告包含：每轨事件数/拍数/时长、省略音符清单、同键重叠警告、低置信位置。

## 六、回滚方案

- **代码回滚**：`cd music_player_next && git checkout main`（或 `git revert` 分支上的提交）。锚点 tag：`pre-multitrack`（= beta.51 提交 d01b811）。
- **产物回滚**：旧 EXE 未被覆盖；`dist/JianpuPlayerNext-v1.0.0-beta.51.exe` 及更早产物原地可用。
- **曲库回滚**：多轨 TXT 以独立文件名（如《可惜没如果（双轨钢琴版）.txt》）入库，不覆盖任何现有文件；删除该文件即完全移除。
- **验证回滚成功**：`python -m unittest discover -s tests -v` 全绿；任选一首老 TXT 播放行为不变。
